# Fabric + Foundry IQ template

A starter for independent **Fabric + Foundry IQ** projects: Terraform infrastructure, Git-versioned Fabric items, a Copilot Studio agent with native IQ tools, a Copilot Managed Runtime app that calls it, and guided Copilot deployment. Derived projects add their scenario workflow; they do not redesign this shell.

> [!IMPORTANT]
> This template is provided as is, without warranty or support, and you use it at your own risk.
> Deploying it creates billable Azure and Fabric resources, registers Entra applications and uses
> preview features. Read the [disclaimer](#disclaimer) before you deploy.

Fabric bootstrap uses native APIs by default: **no GitHub PAT required**.
Set `fabric_git_enabled = true` to opt into Fabric GitHub synchronization.

## What gets created

- **Azure:** resource group and Fabric capacity.
- **Identity/access:** Entra deployment app/service principal, delegated scopes, authorized clients, managed identities and role assignments.
- **Fabric:** DEV/TEST workspaces and DEV-to-TEST deployment pipeline; GitHub credentials connection only with Git synchronization enabled.
- **DEV items:** `Scenario` lakehouse, `ScenarioOntology`, `SeedScenario`, `BindScenario` and `Bootstrap` deployment plan.
- **Seed data:** `dbo.demo_sites` (2 rows), `dbo.demo_assets` (3 rows) and `Files/starter.txt`.
- **Foundry:** account, project, chat/embedding deployments and Search/knowledge/Fabric IQ connections.
- **Search:** service, indexed OneLake source, generated ingestion assets, live ontology source and knowledge base.
- **Web IQ:** global G3 account; portal AppID/key setup is manual.
- **Copilot Studio:** published agent, Fabric IQ/Foundry IQ tools and user connections.
- **Managed Runtime:** app registration and Copilot Studio data source; hosting and sharing are separate.

## Get started

1. Select **Use this template** to create your own repository; it can be private. Don't fork this repository for a project: forks of a public repository are public, and the deployment runner refuses to deploy from them.
2. Open its **Codespace** for the prepared toolchain, or follow [developer setup](docs/development.md) for a local environment.
3. Tell Copilot **"Deploy the platform"**. When using Copilot App with Codespaces, name the Codespace to keep deployment in that checkout and state. It finishes with the agent and app running in the App Player. To skip the agent, run the same [deterministic runner](docs/development.md#deploy-deterministically) yourself: `python3 .github/skills/deploy-platform/scripts/deploy.py up`.

Review [prerequisites and manual steps](docs/getting-started.md) before deploying. You choose the target, sign in, arrange administrator consent and approve the plans. For **configuration only**, use **/initialize-project**.

Use one explicit region by default. Check Fabric CU quota first; the default
serverless Search tier is offered in fewer regions than dedicated tiers, which
also have new-service capacity limits. Approved `fabric_location` /
`search_location` overrides can retain working Foundry resources when a service
is unavailable in that region.

## Delete the environment

From the original derived checkout, with its tfvars, backend and deployment receipts:

```sh
python3 .github/skills/deploy-platform/scripts/deploy.py down --non-interactive
```

Review the saved destroy plan, then approve the reported hash and native deletions:

```sh
python3 .github/skills/deploy-platform/scripts/deploy.py down --non-interactive \
  --allow-delete --approve "destroy=<sha256-prefix>" \
  --approve runtime-delete --approve purge-foundry
```

Deletes the app, agent, Terraform resources and Search ingestion assets; purges the
Foundry account. **Both Fabric workspaces and all their contents are deleted.**
`--yes` cannot approve teardown. Rerun `down` to resume.

Remaining cleanup:

- **Fabric tenant admin:** permanently delete the retained DEV/TEST workspaces; [retention still applies](https://learn.microsoft.com/en-us/fabric/admin/workspace-retention).
- **Power Apps:** remove project-only connections, connection references and retained agent transcripts/solution components; keep reused connections.
- **Web IQ portal:** revoke keys and remove the AppID/profile.
- **Preserved:** GitHub repository, local files/state, backend storage, tenant settings, licenses and external source data.

[Teardown details](docs/development.md#delete-the-environment)

## Scope and boundaries

- **Development baseline:** billable resources, authenticated public endpoints, and preview ontology, deployment-plan and Foundry IQ features.
- **Separate next steps:** TEST starts empty; [native promotion](cicd/README.md) is a separate workflow. PROD, production ingestion, the scenario workflow, hosted app deployment and sharing, and hardening belong to your derived project.
- **Runtime identity:** live ontology retrieval needs an end-user token; managed identity alone is insufficient. See [runtime authentication](docs/ontology-knowledge.md#supply-the-end-users-identity-at-query-time).

The app-facing agent is a standard Copilot Studio agent because the Foundry
Agent Service connector currently fails in Managed Runtime. The knowledge stage
still registers Foundry Fabric IQ connections for that route; see
[routes to re-validate](docs/runtime-integration.md#routes-to-re-validate).
